# 规则库众筹指南（让 103 条滚雪球）

> 机制：用户提交踩坑 → GitHub Issue → 作者审核入待审区 → 转正入库 → 随下个版本分发。知识库越用越准的前提是**源源不断的真实踩坑**。

## 为什么值得提交

- 你的踩坑会变成**带统一编码的规则卡**（RFE-RL-* / RFE-PT-*），被后来者以"如果…那么必须…"的硬结论引用；
- 每条入库规则标注**来源贡献者**（GitHub ID，可选匿名）；
- 审核通过后在下个 Release 的 CHANGELOG 里致谢。

## 提交什么

最有价值的三类素材：

1. **法规踩坑**："做 XX 才知道要办 YY 证，依据是 ZZ 文件"（附官方文件名/编号更好）
2. **死亡点**："因为 XX 设计（如个人收款码收经营性款项），被平台下架/处罚"
3. **提前期实证**："XX 证实际办了 N 天（官方说 M 天）"

## 怎么提交（两种方式）

### 方式 A：GitHub Issue（推荐）

1. 打开仓库 → Issues → 选「踩坑规则提交」模板；
2. 按模板填写：领域（13 类选一）/ 如果…那么必须…格式的规则 / 依据与来源 / 你的经历一句话；
3. 提交即入审核队列。

### 方式 B：本地命令（已安装用户）

```bash
python scripts/rfe.py add --kind rule --domain 招聘与人力 \
  --rule "如果…那么必须…" --severity redline \
  --basis "文件名（文号）" --tags 法规,平台
python scripts/rfe.py doctor   # 提交后跑一次结构自检
```

本地新增先入待审区（`kb_local/`），通过 doctor 结构检查后可随 PR 提交。

## 审核标准（作者承诺 7 天内响应）

| 维度 | 通过标准 |
|---|---|
| 依据可查 | 有官方文件名/编号或可复现的官方入口 |
| 格式正确 | "如果…那么必须…"硬结论，不含"建议/最好"类软话 |
| 领域准确 | 归入 13 领域之一，不与现有规则重复（fingerprint 去重） |
| 无敏感 | 不含具体企业名损誉、不含未公开执法细节 |

不通过会说明原因并给修改建议；法规类规则入库时自动标记 `category: 法规`，进入 90 天复核周期（RFE-DR-103 超期自动降权——过时的众包规则不会误导后来者）。
