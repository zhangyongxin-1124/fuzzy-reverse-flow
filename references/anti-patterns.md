# 反模式：12 种"看起来像推演，其实没推演"

> 对照检查自己的输出。命中 2 条以上，返工重写。

---

## 1. 目录式清单
```
❌ 你需要准备：营业执照、ICP 备案、支付通道、服务器……
✅ 如果平台含多商户在线交易，那么必须持 ICP 经营许可 + EDI（1–3 个月），
   否则属无证经营，罚款并下架；营业执照只是最前面那张纸，不是门槛。
```
**病根**：把"要什么"当"为什么必需"，用户无法判断哪个是生死线。

## 2. 通用废话
"要做好市场调研""要注意合规""要重视用户体验"——任何行业都成立的句子，等于零信息。
**治**：每条结论必须能被"换一个行业就不成立"检验通过。

## 3. 正向流水账
"1. 注册公司 2. 开发 3. 上线 4. 推广"——这是计划书，不是逆向工程。
**治**：从 T0 往回写，每写一步先问"上一刻必须已完成什么"。

## 4. 过度提问
连问八个问题、不给任何推演结果。用户来是为了拿答案，不是填问卷。
**治**：先给猜测 + 默认假设 + 完整推演，最后集中列 3 个必须拍板的变量。

## 5. 假装确定
把"某类许可"写成具体文号，其实是编的；把"约 1 个月"写成"30 个工作日"。
**治**：写不出准确名称就写"名称待属地确认"，并给官方入口。

## 6. 只谈合规不谈商业
列一堆证照，却不回答"谁会来买"。电商死在没商家，不是死在没 EDI。
**治**：死亡点清单里至少 2 条必须是商业侧。

## 7. 无视主体差异
把企业门槛套在个人身上（"你去办个增值电信许可"——个人根本不能办）。
**治**：每条硬性条件后加"对谁成立"。

## 8. 时间乐观主义
资质写"1 个月"，开发写"1 个月"，上线写"下个月"，总周期写"3 个月"。
**治**：外部审批加 30%–50% 缓冲，并给出"最坏情况"口径。

## 9. 里程碑不可验收
"完成开发""推进中""基本搞定"——无法判断真假。
**治**：交付物 = 数量/编号 + 凭证 + 时点。

## 10. 没有降级路线
一条道走到黑，某个证下不来就全盘停摆。
**治**：每份倒排期附一条"若 X 不成立 → 改为 Y"。

## 11. 不落库
推演完就结束，下次同类问题从零开始，用户感觉不到"越用越聪明"。
**治**：每次至少萃取 1 条规则或 1 条坑，`add` 入库并回执。

## 12. 越界给法律意见
替用户判断"这个合同条款有效""你这样不算违法"。
**治**：给"风险等级 + 依据 + 核实入口"，把定性结论留给执业律师。

---

## 附：一句话自检口诀

> **有前提吗？有周期吗？对谁成立？不做的后果是什么？今天能干的第一件事是什么？**
> 五问全答上，才算一份合格的逆向推演。
