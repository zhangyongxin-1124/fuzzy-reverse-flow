# 海外合规图层（GDPR / CCPA 起步，v1.5.0 实验性）

> 定位：为"做出海产品"的用户提供方向性合规图层。**这是实验性内容**——条目密度远低于中国本土规则库，结论均为"必须进一步核实"级别，不是可执行红线。重大出海决策请咨询目标市场的执业律师。

## 使用方式

- 对 AI 说："我做一个面向欧洲用户的 XX App，倒推一下合规路径"——领域判定到"出海合规"时叠加本图层；
- CLI：`rfe recall --query "..." --domain 出海合规`；
- 与中国本土规则**叠加校验**而非替代：服务器在中国、用户在欧洲 = 两边规则同时适用。

## 起步条目（EU · GDPR，均为方向性提醒）

| # | 方向性结论 | 需进一步核实 |
|---|---|---|
| GL-EU-1 | 如果产品面向欧盟用户提供服务并处理个人数据（无论服务器在哪），那么大概率适用 GDPR，需指定 EU 代表并准备数据处理记录（Art.30） | EDPB 官网；Member State 差异 |
| GL-EU-2 | 如果处理儿童数据，那么需要家长同意机制与年龄验证设计（Art.8） | 各国年龄线不同（13-16） |
| GL-EU-3 | 如果发生数据泄露，那么 72 小时内必须向监管机构通报（Art.33） | 成员国监管机构入口 |
| GL-EU-4 | 如果把欧盟数据传回非欧盟服务器，那么需要 SCC 等传输合法化机制（Chapter V） | 最新 SCC 版本（2021 后） |
| GL-EU-5 | 如果用户行使被遗忘权/可携带权，那么产品必须内建导出与删除功能（Art.15-22）——**这直接影响产品设计，必须在需求阶段就进入** | 控制者/处理者角色划分 |

## 起步条目（US · CCPA/CPRA，加州为基准）

| # | 方向性结论 | 需进一步核实 |
|---|---|---|
| GL-US-1 | 如果满足加州居民数据 + 营收/数据量门槛，那么适用 CCPA/CPRA，需提供"Do Not Sell/Share My Personal Information"入口 | 门槛年度值随 CPI 调整 |
| GL-US-2 | 如果面向儿童，那么 COPPA 要求家长同意（13 岁线），FTC 执法活跃 | FTC 官网 |
| GL-US-3 | 其他州（弗吉尼亚/科罗拉多/犹他/康涅狄格…）已陆续生效各自隐私法，多州运营取最严交集 | 各州 AG 入口 |

## 维护说明

- 本图层**不进入** 90 天法规复核自动降权机制（因为条目本身即"需核实"级别，不承诺硬结论）；
- 扩充优先级：用户提交出海踩坑（见 docs/规则库众筹指南.md）→ 作者核实 → 转正为带编码规则卡；
- 长期路线：GDPR 精化 → 英文版规则卡 → 更多法域（参考 README Roadmap）。
