# 阶段二：逆向硬性条件反推（Reverse Prerequisites）

> 核心提问方式：**假设 T0 已经达成，那么在此之前必须已经为真的事实是什么？**
> 注意词：**必须**。不是"最好有"，不是"建议了解"，是"没有就不成立"。

---

## 1. 六层合规扫描法（任何行业通用）

按顺序扫，上一层不成立时，下层的许可根本无从谈起。

| 层 | 问什么 | 典型产出 |
|---|---|---|
| L1 主体 | 谁来做？个人/个体户/有限公司？经营范围写什么？有没有人数/资金/场所门槛？ | 营业执照、经营范围条目 |
| L2 备案 | 有没有线上载体？服务器在哪？域名实名了吗？ | ICP 备案、公安备案、App/小程序备案 |
| L3 许可 | 业务是否属于需前置/后置许可的类别？ | ICP 证、EDI、人力资源服务许可、食品经营许可、办学许可 |
| L4 专项 | 是否触碰金融/医疗/教育/出版/视听/征信等特许领域？ | 支付牌照、互联网医院、广播电视节目制作经营许可、微短剧备案 |
| L5 内容 | 有没有 UGC、AI 生成、广告、未成年人？ | 内容审核机制、AI 标识、广告标识、未成年人模式 |
| L6 数据 | 收集什么数据？存哪？给谁？出境吗？ | 隐私政策、单独同意、PIA、等保、出境评估 |

**快速判据**：
- 收钱 → L3 经营性许可
- 有别人发的内容 → L5
- 有身份证/健康/位置/人脸 → L6 敏感个人信息
- 面向公众生成内容 → L4+L5（算法备案 + AI 标识）

## 2. 通用十问（拿到任何需求先过一遍）

1. 主体是什么？经营范围够不够？
2. 要不要备案？谁去备？多久？
3. 收不收钱？收钱的方式算不算"经营"？
4. 有没有第三方（商家/服务者/创作者）？平台要替他们担什么责？
5. 资金怎么走？有没有沉淀？
6. 收集哪些个人信息？哪些是敏感信息？
7. 内容谁审？审不过来怎么办？
8. 有什么资质是"申请了就一定拿不到"的（如个人申请增值电信）？
9. 哪一项审批周期最长？它决定项目下限。
10. 出事后谁担责：平台、商家、还是个人？

## 3. 资源底线算法（不是预算表，是"低于此线必死"）

分三桶，各桶独立核算，不要互相挪用：

### 桶 A：一次性硬成本
资质代办/自办费 + 认证检测费 + 软著商标 + 测评（等保/隐私检测）+ 法务合同

### 桶 B：每月固定成本
人力（含社保）+ 服务器/云服务 + 合规维护（审核岗、安全巡检）+ 工具订阅

### 桶 C：冷启动成本
获客（CAC × 目标用户数）+ 供给补贴（商家/岗位/创作者）+ 履约兜底（赔付金/保险）

**底线公式**：
```
可支撑月数 = (现金 - 桶A) / (桶B + 桶C/目标月数)
若 可支撑月数 < 资质周期(月) + 3 ，则方案不可行
```
这个公式能一眼看出"钱不够撑到证下来"的项目——这是最常见的死法。

### 人力底线（三个不可外包的角色）
- **能签字担责的人**：法人/合规负责人（平台出事第一个被找的人）
- **能过审的人**：内容/资质审核（不是客服兼职）
- **能拍板的人**：需求变更的最终裁决者（没有它，项目必延期）

## 4. 死亡点清单（比风险清单更狠）

每条必须写全五段，否则不算完成：

```
死亡点：<一句话命名>
触发条件：<什么情况下会发生>
症状：<发生时你看到什么>
早期信号：<提前 2-4 周能观察到的征兆>
预防动作：<现在就该做的一件事>
兜底方案：<已经发生时的止血动作>
```

**通用高频死亡点**（按行业命中率排序）：
1. 供给不足（商家/岗位/创作者不来）— 电商、招聘、内容平台的第一死因
2. 资质卡壳（周期被低估 2 倍）— 所有强监管行业
3. 资金合规（二清、个人账户、预付跑路）— 交易类
4. 内容翻车（擦边/侵权/虚假宣传）— 内容与广告
5. 成本失控（推理成本、履约成本）— AI 与本地生活
6. 关键人依赖（只有一个懂的人）— 所有小团队

## 5. 推导句式库（直接套用）

| 场景 | 句式 |
|---|---|
| 资质 | 如果 <业务特征>，那么必须取得 <具体许可名称>，否则 <具体后果> |
| 主体 | 如果 <主体类型>，那么 <许可> 不可申请/门槛提高，须改为 <主体形态> |
| 周期 | 如果 <许可> 未在 <T-N 周> 前提交，那么 T0 上线必然延后 <周期> |
| 范围 | 如果 含 <UGC/交易/直播/跨境>，那么必须增加 <义务>，工期 +<N> 周 |
| 资金 | 如果 平台代收代付，那么必须走 <持牌分账>，不得 <资金池> |
| 数据 | 如果 收集 <敏感信息>，那么必须 <单独同意 + 加密 + 影响评估> |
| 资源 | 如果 预算 < X，那么 不能自研 <Y>，应改为 <Z> |
| 风险 | 如果 <条件> 发生，那么可能 <行政处罚/连带赔偿/刑事>，因此必须 <预防动作> |
| 不适用 | 如果 范围不含 <X>，那么 <相应许可> 不适用，但 <替代义务> 仍在 |

**禁用词**（承载硬性条件时）：建议、可以考虑、最好、酌情、一般来说、视情况。

---

## 6. 输出格式

三张表 + 一段结论：

1. **合规红线表**：ID / 条件 / 等级（红线·阻断·提示）/ 对谁成立 / 提前期 / 可信度 / 依据 / 后果
2. **资源底线表**：类别 / 底线 / 估算 / 说明
3. **死亡点清单**：五段式，只保留前 4–6 个真正致命的
4. **一段结论**：把"最硬的一道门槛"单独拎出来说，因为用户 90% 的决策只取决于这一条
