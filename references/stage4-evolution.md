# 阶段四：自我演化（规则萃取 + 闭坑记忆）

> 一个不记录的推演，只能聪明一次。
> 这一阶段把"这次的经验"变成"下次的默认前提"。

---

## 1. 两类持久化对象

| 对象 | 文件 | 回答的问题 | 何时写入 |
|---|---|---|---|
| **规则卡**（rule） | `rules.jsonl` | "这个领域必须满足什么" | 每次推演后 1–3 条 |
| **坑卡**（pitfall） | `pitfalls.jsonl` | "上次在哪里死的、怎么死的" | 踩到或预判到坑时立即写 |

区别：规则是**事前要求**（进阶段二），坑是**事后记忆**（进阶段二面 C 与阶段三的风险节点）。

---

## 2. 规则萃取的四道闸门

一条候选规则必须同时通过四问，否则不写：

1. **可迁移？** 换个同类项目还成立吗？（"我们 11 月上线"✗，"电商必须双证"✓）
2. **有后果？** 说得出不遵守会发生什么具体后果吗？（说不出 → 只是建议，不是规则）
3. **有主体？** 说得出对谁成立吗？（个人/个体户/企业/平台）
4. **可验证？** 能指向一个官方入口、平台规则页或标准文本吗？

**四问全过 → 写规则卡；只过 1、2 问 → 写坑卡；都不过 → 不写。**

---

## 3. 规则的质量分级

| 字段 | 取值 | 含义 |
|---|---|---|
| `severity` | `redline` | 违反即违法/不可能补救，必须前置解决 |
| | `blocker` | 违反会卡住上线/上架/签约，但可整改 |
| | `advisory` | 影响成本或效率，不致命 |
| `confidence` | `high` | 有明确法规/标准/官方文件支撑 |
| | `medium` | 有依据但属地/口径存在差异 |
| | `low` | 行业经验，尚未验证 |
| `basis_level` | `law` / `regulation` / `rule` / `policy` / `standard` / `license` / `platform` / `practice` | 依据的效力层级，决定推演时的"硬度" |
| `verified_at` | 日期或 null | 上次人工核实日期；超 180 天由 `doctor` 标记 stale |

**写规则时最容易犯的错**：把所有内容都标成 `redline` + `high`。这会摧毁召回信号的价值。
正确做法：只有"违反即不可补救"的才配 `redline`。

---

## 4. 召回机制（怎么做到"越用越聪明"）

打分 = 二元组重合 + 触发器命中(×3) + 领域命中(×2) + 等级权重 + 历史命中数(×0.25) − 废止惩罚
再做**领域亲和降权**：与推断领域不符的专门领域规则 ×0.55，避免跨领域噪声。

因此系统会自然形成三种"变聪明"：
1. **用得越多排得越前**（`hit_count` 累积）——常用红线形成肌肉记忆。
2. **新领域自动扩展**（新增种子文件即可，无需改代码）。
3. **旧规则会被推翻**（`status: deprecated` + `verify` 更新）——不会拿过期口径误导人。

---

## 5. 坑 → 规则的升级机制

```
第 1 次遇到 → 记坑卡（pitfall, severity=blocker）
第 2 次遇到（同类场景再现）→ 在坑卡里 seen_count +1，并在下次推演时前置提示
第 3 次遇到 → 升级为规则卡（rule, severity=redline），同时把坑卡 status 置 resolved
```

命令行：

```bash
python scripts/rfe.py pitfall add --file pit.json     # 记坑
python scripts/rfe.py pitfall recall -q "电商 上线"    # 推演前查雷
python scripts/rfe.py add --file rule.json            # 升格为规则
```

**判定"同类"的标准**：`domain` 相同 + `trigger` 有交集，不要求文字相同。

---

## 6. 维护节奏

| 频率 | 动作 | 命令 |
|---|---|---|
| 每次推演后 | 写 1–3 条规则 / 坑 | `add` / `pitfall add` |
| 每周 | 看看最常命中规则是否需要细化 | `stats` |
| 每月 | 核对 `stale` 规则，更新核实状态 | `doctor` + `verify` |
| 每季度 | 导出共享给团队，做一次去重合并 | `export -F md -o rules.md` |

---

## 7. 演化边界（防止知识库腐化）

- **不写项目专有事实**：报价、人名、内部排期不进规则库。
- **不写推测**：`confidence: low` 的规则必须带 `verify_url`，否则下次召回会误导。
- **不写无法执行的**："要注意合规"这类不可执行句没有价值。
- **遇到信息冲突时**：写两条并标 `note: 行业信息冲突，以平台/属地最新公告为准`，而不是二选一赌一个。

```
【阶段四 · 规则萃取】
本次沉淀 2 条：
  RULE-ECOM-0011（redline）如果多商户在线交易 → 必须 ICP+EDI 双证，提前期 1-3 个月
  PIT-0003（blocker）坑：先上线后补证 → 小程序被限制访问，恢复耗时 3 周
已入库（~/.workbuddy/reverse-engine），下次同类场景将自动前置提示。
```
